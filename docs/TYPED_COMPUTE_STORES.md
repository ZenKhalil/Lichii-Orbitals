# Typed compute buffer stores

Some native compute shaders use an unformatted, write-only buffer image with views whose numeric class changes between dispatches. Emitting that image as unsigned for a signed or floating-point view violates Vulkan's sampled-type contract. This change keeps the prepared view and selects a matching unsigned, signed, or floating-point pipeline.

## Supported contract

The family is restricted to native compute programs with exactly one static, count-one, Typeless storage buffer image, with stores and no reads. Other texture/image declarations, dynamic handles, image atomics, coherent or byte-addressed modes, and scaling-sensitive image fetch/query/attribute operations are excluded. The promoted host formats are R32_UINT, R32_SINT, R32_SFLOAT, and R32G32B32A32_SFLOAT. Vulkan 1.3, storage-write-without-format support, and the required per-format buffer features are checked.

Unsupported programs, formats, devices, or unavailable/conflicting input capture retain the existing pipeline behavior. That fallback can retain preexisting numeric mismatches. Replay inconsistencies and failed eligible members are shader compilation failures, not successful partial families. The separate graphics uniform-buffer numeric mismatch is outside this change.

## Compiler inputs and ownership

Cold translation records query answers while returning the existing values. An immutable snapshot owns the code, native address map, compiler metadata, and query maps; missing or conflicting inputs reject capture/replay. Warm translation snapshots the loaded disk record without changing its serialization format or inclusive instruction-read boundary. Cold snapshots preserve the producer's exclusive upper read boundary.

Each family member receives a fresh environment, CFG, and instruction/block pools. The initial translation and all three replays share captured translation options, host capabilities, profile, and loop-safety choice. Full pre- and post-emission metadata is compared. IR is never reused after emission.

The sampled scalar and four-component store operand change together. Signed and floating-point stores bitcast the existing U32x4 carrier; they do not numerically convert it. View format, component count, offset, size, and texel stride remain unchanged. Arbitrary NaN payload preservation through floating-point format conversion is not promised.

All modules exist before pipeline construction. Family pipelines build synchronously, avoiding queued callbacks into partially constructed objects. Shader notification completion is scoped around each constructor, null pipelines are rejected, and the original-class base owns the other members. Complete metadata and descriptor layouts must agree. Existing cache retirement retains the entire family and checks every member's build completion.

Configure prepares resources once. A one-entry observation in the existing descriptor update queue records the actual view/format/offset/size, including null substitution, without another guest read, view creation, or driver query. The selected member is captured by value for binding and both direct and indirect dispatches, including deferred binding. Diagnostic rows use the selected compiled class before reserving their log quota.

## Validation and limits

The integrated source passed:

- Nine actual translator/input replay cases, 184 assertions, including fresh Phi/flag operations, native map/read boundaries, missing inputs, conflicts, and warm serialization replay.
- Four typed-store cases, 9,445 assertions, covering eligibility exclusions, emitted scalar/store operand types, bitcasts, format features, and diagnostic classification.
- The combined 140-case regression selection, 51,840,250 assertions.
- The existing shader/compiler/pipeline-cache selection, 95 cases and 448,211 assertions. These selections overlap; their case counts are not additive coverage.
- A standalone 28-check extraction/projection of the actual descriptor queue methods, including consumed/reset observations and immutable A-to-B selection. This is not an actual Device/Scheduler/ComputePipeline integration test.
- Eight headless Vulkan cases using modules generated by the actual emitter. R32 unsigned/signed/float and RGBA32 float finite values, integer extremes, repeated format selection, and canaries passed with Core and synchronization validation enabled and zero validation errors. Special floating-point values were recorded separately from portable exact-value assertions.

Initial replay fixtures omitted the MOV32I write mask and therefore produced undefined data instead of Phi nodes. Two exclusion fixtures initially contained pre-TexturePass bindless operations rather than the normalized operations consumed by eligibility. Those test-only errors were corrected; they are not evidence of production regressions. Fresh-IR comparisons exclude host instruction-address prefixes from debug dumps.

The synthetic value test does not execute the emulator's Configure, cache retirement, or guest compiler input collection. Partial driver-construction failure injection and full scheduler lifetime behavior remain source-reviewed boundaries. A fresh GUI validation run is required for actual family selection, warm/cold gameplay behavior, and visible results. No artifact or FPS improvement is claimed by these tests.

Eligible shaders incur an initial translation plus three fresh translations and three eager pipelines, which can increase compilation time and memory. Ineligible shaders retain their existing asynchronous path. No configuration defaults, game data handling, or on-disk shader format are changed.
